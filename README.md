# PII Masker (PDF + Excel)

Веб-сервис: пользователь входит, загружает PDF или Excel, сервис возвращает обезличенный файл. Персональные данные заменяются похожими ненастоящими значениями, поэтому текст остаётся осмысленным, но не содержит настоящих данных.

## Запуск

1. Установить зависимости: `setup.bat`
2. Запустить LM Studio, загрузить модель и включить локальный сервер (по умолчанию `http://127.0.0.1:1234/v1`). LLM — основной анализатор; без неё сервис продолжит работу на регулярках, но качество поиска ФИО/организаций/адресов будет ниже.
3. Запустить `python main.py` (или `.venv\Scripts\python.exe main.py`).
4. Откроется `http://127.0.0.1:9321`. Для доступа с других ПК — `http://<IP-компьютера>:9321`.

Учётка по умолчанию: `admin / admin` (файл `data/users.json`).

## Настройки (`settings.json` рядом с main.py/exe)

```json
{
  "lm_studio_url": "http://127.0.0.1:1234/v1",
  "model": "google/gemma-4-e2b",
  "api_key": "lm-studio",
  "temperature": 0.0,
  "max_tokens": 2048,
  "request_timeout": 120,
  "max_llm_chars": 30000,
  "llm_chunk_chars": 4000,
  "llm_enabled": true,
  "host": "0.0.0.0",
  "port": 9321,
  "open_browser": true
}
```

`host: 0.0.0.0` открывает доступ по IP. Для доступа только с этого ПК: `127.0.0.1`.

## Что заменяется

- ФИО — фейковое ФИО (с подмешиванием случайных букв).
- Телефоны, email, адреса, организации — фейковые значения того же формата.
- ИНН, КПП, ОГРН/ОГРНИП, СНИЛС, паспорт, счета (20 цифр), БИК — другие числа/номера с сохранением формата.
- Суммы, количества и прочие числа — другие числа той же длины, с теми же разделителями.
- Даты — сдвиг на случайное количество дней.

Одинаковые исходные значения в пределах одного документа заменяются одинаково (кэш фейков).

- **Основной анализатор — LLM.** Модель читает документ и сама возвращает список того, что нужно заменить (ФИО и его части, организации, адреса и их части, должности, подписи, реквизиты), а инструмент применяет замену. Поиск идёт по смыслу, а не только по шаблонам, поэтому находятся ФИО в ВЕРХНЕМ РЕГИСТРЕ, в кавычках, в блоках электронной подписи и в нестандартном оформлении.
- Для каждой найденной сущности дополнительно ищутся её варианты: фамилия отдельно, инициалы (`Иванов И.И.`, `И.И. Иванов`), короткое название организации, город/улица из адреса. Одинаковые значения заменяются одинаково по всему документу.
- PDF: поиск идёт по всему блоку/строке, а не по отдельному span. Поэтому ФИО и организации, разбитые жирным шрифтом, курсивом или другим начертанием на несколько span, всё равно находятся и заменяются. Исходный текст вырезается через redaction, поверх рисуется фейковый текст с сохранением начертания (жирный/курсив) и цвета. Метки `ИНН`, `КПП`, `ОГРН` не сдвигаются.
- PDF-таблицы: строки найденных таблиц склеиваются по ячейкам, поэтому ФИО/организация/адрес, разбитые по колонкам, тоже находятся. Ширина фейкового текста ограничивается ячейкой таблицы и соседним текстом, чтобы замена не вылезала в соседнюю колонку. Повёрнутый текст (вертикальный, на 90/180/270°) перерисовывается с тем же поворотом.
- PDF-служебные данные: очищаются свойства документа (автор, тема, ключевые слова, даты), XMP-метаданные, закладки, текстовые свойства комментариев/аннотаций, подписи и значения полей форм, а также ссылки, в которых найдены email/телефон.
- Excel: строка таблицы склеивается для поиска, поэтому ФИО, разбитое по колонкам «Фамилия / Имя / Отчество», тоже заменяется. Числовые ячейки получают фейковые числа, даты сдвигаются. Дополнительно очищаются комментарии, колонтитулы, гиперссылки в изменённых ячейках, строковые литералы формул, rich-text и свойства книги (автор, тема, описание, пользовательские поля). Книга и форматирование сохраняются.
- Регулярки остаются страховочной сетью для структурированных данных (ИНН, ОГРН, БИК, счета, телефон, email, даты, числа) и работают, даже если LM Studio недоступен. Сущности от LLM имеют приоритет над регулярками.
- LLM (LangChain + LM Studio): если модель недоступна, обработка продолжается на регулярках; в ответе API будет `llm_used: false`.

## RAG

RAG на LangChain (`InMemoryVectorStore` + локальные hash-эмбеддинги, без внешних вызовов). Правила лежат в `main.py` и могут дополняться файлами `data/knowledge/*.txt`. RAG используется только как контекст для необязательного поиска дополнительных ПДн через LLM. AI-помощника, чата и инструментов в интерфейсе нет.

## Сборка exe

`build.bat` → `dist\PIIMasker.exe`. Рядом с exe создаются `settings.json` и `data/`. При запуске сайт открывается автоматически.

## Ограничения

- Поддерживаются PDF с текстовым слоем и Excel `.xlsx` (не `.xls`). Сканы без OCR не обрабатываются: текст на изображениях заменить нельзя.
- PDF с паролем не поддерживаются.
- Текст в векторных кривых (не настоящий текстовый слой) и вложенные файлы PDF не обезличиваются. Цифровые подписи после изменения документа становятся недействительными — это неизбежно при редактировании PDF.
- Автоматическое определение таблиц работает по линиям/сетке, а для «безграничных» таблиц включается страховка: рядом стоящие блоки на одной высоте с небольшим зазором склеиваются в строку. Сложные многоуровневые шапки и ячейки с сильно разным вертикальным выравниванием могут определяться частично.
- LLM анализирует первые `max_llm_chars` символов документа (по умолчанию 30 000). Для очень длинных документов увеличьте значение в `settings.json`; остальной текст всё равно обрабатывается регулярками.
- История обработки не хранится; готовые файлы лежат в `data/outputs`.
