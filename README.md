# PII Masker (PDF, Word, Excel, изображения)

Веб-сервис: пользователь входит, загружает PDF, Word (.docx), Excel (.xlsx) или изображение (PNG/JPG), сервис возвращает обезличенный файл. Персональные данные заменяются похожими ненастоящими значениями, поэтому текст остаётся осмысленным, но не содержит настоящих данных.

## Запуск

1. Установить зависимости: `setup.bat`
2. Запустить LM Studio, загрузить модель и включить локальный сервер (по умолчанию `http://127.0.0.1:1234/v1`). Модель может быть не загружена заранее: LM Studio загрузит её по требованию (JIT) при первом запросе, сервис подождёт до `model_load_timeout` секунд. LLM — основной анализатор; без неё сервис не обрабатывает документы.
3. Запустить `python main.py` (или `.venv\Scripts\python.exe main.py`).
4. Откроется `http://127.0.0.1:9321`. Для доступа с других ПК — `http://<IP-компьютера>:9321`.
5. В интерфейсе можно выбрать сразу несколько файлов. Они уходят в LM Studio строго по одному; таблица файлов заполняется по мере готовности, и каждый готовый файл скачивается отдельно, не дожидаясь остальных.

Учётка по умолчанию: `admin / admin` (файл `data/users.json`).

## Настройки (`settings.json` рядом с main.py/exe)

```json
{
  "lm_studio_url": "http://127.0.0.1:1234/v1",
  "model": "google/gemma-4-e2b",
  "api_key": "lm-studio",
  "temperature": 0.0,
  "max_tokens": 2048,
  "request_timeout": 120,
  "model_load_timeout": 600,
  "llm_retries": 3,
  "max_llm_chars": 30000,
  "llm_chunk_chars": 4000,
  "llm_enabled": true,
  "ocr_lang": "rus+eng",
  "host": "0.0.0.0",
  "port": 9321,
  "open_browser": true
}
```

`host: 0.0.0.0` открывает доступ по IP. Для доступа только с этого ПК: `127.0.0.1`.
`model_load_timeout` — сколько секунд ждать загрузку модели по требованию (JIT) в LM Studio. `ocr_lang` — языки Tesseract для PNG/JPG.

## Что заменяется

- ФИО — фейковое ФИО (с подмешиванием случайных букв).
- Телефоны, email, адреса, организации — фейковые значения того же формата. Названия сторон договора ищутся после подписей «Поставщик», «Покупатель», «Заказчик», «Исполнитель», «Подрядчик», «Арендодатель», «Сторона 1/2» и т.п., включая полные юридические формы («Общество с ограниченной ответственностью …», «Акционерное общество …», «Индивидуальный предприниматель …»).
- ИНН, КПП, ОГРН/ОГРНИП, СНИЛС, паспорт, счета (20 цифр), БИК — другие числа/номера с сохранением формата. Наименования банков в реквизитах тоже заменяются.
- Суммы, цены платежей, авансы, штрафы/пени/неустойки, количества и прочие числа — другие числа той же длины, с теми же разделителями. Валюта и единицы измерения сохраняются.
- Даты и сроки (поставки, оплаты, гарантии) — заменяются другими датами; числа в сроках (дни, недели, месяцы, годы) — другими числами с сохранением склонения. Суммы и сроки прописью без цифр заменяются нейтральной пометкой «по договору», а числительные в скобках — «(сумма прописью)».
- Наименования товаров, работ и услуг — конкретные значения в таблицах и тексте (включая перечисления через запятую) заменяются нейтральными номерами позиций; заголовки колонок («Товар», «Услуга», «Наименование») не трогаются.

Одинаковые исходные значения в пределах одного документа заменяются одинаково (кэш фейков).

- **Основной анализатор — LLM.** Модель читает документ и сама возвращает список того, что нужно заменить (ФИО и его части, организации, адреса и их части, должности, подписи, реквизиты), а инструмент применяет замену. Поиск идёт по смыслу, а не только по шаблонам, поэтому находятся ФИО в ВЕРХНЕМ РЕГИСТРЕ, в кавычках, в блоках электронной подписи и в нестандартном оформлении.
- Для каждой найденной сущности дополнительно ищутся её варианты: фамилия отдельно, инициалы (в обоих порядках), короткое название организации, город/улица из адреса. Одинаковые значения заменяются одинаково по всему документу.
- PDF: поиск идёт по всему блоку/строке, а не по отдельному span. Поэтому ФИО и организации, разбитые жирным шрифтом, курсивом или другим начертанием на несколько span, всё равно находятся и заменяются. Исходный текст вырезается через redaction, поверх рисуется фейковый текст с сохранением начертания (жирный/курсив) и цвета. Метки `ИНН`, `КПП`, `ОГРН` не сдвигаются.
- PDF-таблицы: строки найденных таблиц склеиваются по ячейкам, поэтому ФИО/организация/адрес, разбитые по колонкам, тоже находятся. Ширина фейкового текста ограничивается ячейкой таблицы и соседним текстом, чтобы замена не вылезала в соседнюю колонку. Повёрнутый текст (вертикальный, на 90/180/270°) перерисовывается с тем же поворотом.
- PDF-служебные данные: очищаются свойства документа (автор, тема, ключевые слова, даты), XMP-метаданные, закладки, текстовые свойства комментариев/аннотаций, подписи и значения полей форм, а также ссылки, в которых найдены email/телефон.
- Excel: строка таблицы склеивается для поиска, поэтому ФИО, разбитое по колонкам «Фамилия / Имя / Отчество», тоже заменяется. Числовые ячейки получают фейковые числа, даты сдвигаются. Дополнительно очищаются комментарии, колонтитулы, гиперссылки в изменённых ячейках, строковые литералы формул, rich-text и свойства книги (автор, тема, описание, пользовательские поля). Книга и форматирование сохраняются.
- Word (.docx): абзац склеивается из всех runs, поэтому ФИО/организация, разбитые на части форматированием, тоже заменяются с сохранением структуры и оформления. Дополнительно очищаются колонтитулы, сноски, комментарии и свойства документа (автор, тема, название, ключевые слова). Старый `.doc` автоматически преобразуется в `.docx` через Microsoft Word или LibreOffice, результат скачивается как `.docx`.
- Изображения (PNG/JPG): текст распознаётся OCR (Tesseract с языками `rus+eng`, если установлен; иначе — мультимодальная модель LM Studio). Найденные ПДн закрываются плашкой и заменяются фейковым текстом; EXIF-метаданные не сохраняются.
- Регулярки остаются страховочной сетью для структурированных данных (ИНН, ОГРН, БИК, счета, телефон, email, даты, числа). Сущности от LLM имеют приоритет над регулярками.
- LLM (LangChain + LM Studio): если модель не загрузилась или не отвечает, документ не выдаётся (`llm_used: false` только при частичном ответе).

## RAG

RAG на LangChain (`InMemoryVectorStore` + локальные hash-эмбеддинги, без внешних вызовов). Правила лежат в `main.py` и могут дополняться файлами `data/knowledge/*.txt`. RAG используется только как контекст для необязательного поиска дополнительных ПДн через LLM. AI-помощника, чата и инструментов в интерфейсе нет.

## Сборка exe

`build.bat` → `dist\PIIMasker.exe`. Рядом с exe создаются `settings.json` и `data/`. При запуске сайт открывается автоматически.

## Ограничения

- Поддерживаются PDF с текстовым слоем, Word `.doc`/`.docx`, Excel `.xlsx` (не старый `.xls`) и изображения PNG/JPG. Для `.doc` нужен Microsoft Word или LibreOffice (конвертация в `.docx`). Сканы PDF без OCR не обрабатываются: текст на изображениях заменить нельзя. Для изображений нужен Tesseract (`rus+eng`) или мультимодальная модель LM Studio.
- Логи: `data/activity.log` (действия, задания, LLM) и `data/server.log` (сервер, uvicorn). Пишутся и в обычном запуске, и в exe.
- PDF с паролем не поддерживаются.
- Текст в векторных кривых (не настоящий текстовый слой) и вложенные файлы PDF не обезличиваются. Цифровые подписи после изменения документа становятся недействительными — это неизбежно при редактировании PDF.
- Автоматическое определение таблиц работает по линиям/сетке, а для «безграничных» таблиц включается страховка: рядом стоящие блоки на одной высоте с небольшим зазором склеиваются в строку. Сложные многоуровневые шапки и ячейки с сильно разным вертикальным выравниванием могут определяться частично.
- LLM анализирует первые `max_llm_chars` символов документа (по умолчанию 30 000). Для очень длинных документов увеличьте значение в `settings.json`; остальной текст всё равно обрабатывается регулярками.
- История обработки не хранится; готовые файлы лежат в `data/outputs`.
